## 1. 背景と目的

直方市の ArcGIS ダッシュボード「災害時情報共有PF(公開用)」をモバイルアプリ化し、AR 浸水体験による「危険度の体感」を加えた作品を、第15回 e-ZUKA スマートアプリコンテスト2026(一般の部)に出品する。

- **直接ゴール**: コンテスト出品(動くアプリ+デモブース+プレゼン)。テーマ「Innovative Hack for Local in 飯塚」の災害分野
- **将来像**: 防災を看板機能とした市民生活ポータル(ごみ収集日・子育て・市のお知らせ等)へ発展させる。本リリースの情報設計はこの将来像を妨げない形にする

## 3. スコープ

### 3.1 コンテスト版に含む

1. 市の防災データ 5 レイヤーの表示(避難所・水位センサー・転倒ゲート・被害報告・交通規制)
2. ハザードマップ(洪水浸水想定)の地図オーバーレイ
3. AR 浸水体験(最低ライン: 平面検出+手動スライダー水面)
4. デモモード(模擬災害シナリオ、オフライン動作)
5. 川の防災情報(kawabou)へのリンクアウト
6. じぶん設定(自宅ピン等)による表示のパーソナライズ — 最小実装(F-12)
7. やさしい日本語モード(固定 UI 文言と安全に関わる注意書きの平易化)— 最小実装(F-13)
8. 人口レイヤー(500mメッシュの推計人口を地図に重ねる)— プロトタイプ(F-14)
9. 地震ハザードレイヤー(J-SHIS の 250m メッシュと福智山断層帯)— v1.6(F-15)
10. 地形分類レイヤー(治水地形分類図)— v1.6(F-16)
11. 自然災害伝承碑のピン — v1.6(F-17)
12. 公式情報への導線と偽情報への注意書き — v1.6(F-18)

v1.6 では、令和8年熊本地震(2026-07-28)の教訓を最終審査のプレゼンの前面に出す方針(2026-09-12 決定)に沿って、地震を守備範囲に入れた。
あわせて F-01(地図の操作 UI)、F-02(避難所の対応災害の明示)、F-07(土砂2区域の統合)、F-09(地震シナリオ)、F-12(徒歩分数と災害種別ごとの最寄り)、F-14(塗りの排他)を拡張した。
背景は `docs/kumamoto-2026-lessons.md`、設計は `docs/design/v1.6-design.md` にある。

### 3.2 コンテスト版に含まない(将来要件)

- プッシュ通知(避難所開設・警報等) — 常時監視サーバが必要なため将来要件
- Android 対応、ストア公開
- 生活ポータル機能(ごみ・子育て・お知らせ等)
- 多言語対応(英語やベトナム語などへの翻訳)、アカウント・ログイン。「やさしい日本語モード」は日本語1言語のアクセシビリティ機能のため本版に含む(§3.1 の 7、F-13)
- 遠賀川本川水位の生値取り込み(FRICS 有償配信。kawabou リンクアウトで代替)
- 被害報告の投稿機能(市の運用に関わるため。閲覧のみ)
- 避難所の設備情報(冷房、非常用電源、ペット、福祉避難所)、応急給水拠点、市の浸水実績図の地図化。いずれも市への確認が要るため最終審査後に扱う(2026-09-12 決定)
- わが家の防災カルテ、根拠つきの知識カード、家族の決めごと、遠賀川水位の歴史目盛り、年表画面(`docs/kumamoto-2026-lessons.md` §5.4、`docs/nogata-disaster-history.md` §5)。最終審査後の要件にする
- 車中泊や在宅避難の自己申告、利用者投稿による災害マップ。常時稼働のサーバと投稿の確認体制が要り、位置情報を外部へ送ることになるため(NF-07)、市のシステム側の課題として提案書に書く
- 地震版の AR(揺れや家具の転倒)。ARKit で揺れの体感を作りにくく、AR は水害のみとする(2026-09-12 決定)
- 人口可視化の拡張(小地域(町丁字)単位の内訳、浸水域と重ねた要約表示)。500mメッシュの人口レイヤーは F-14 として本版に含む(v1.5)。RESAS-API は 2025-03-24 に提供を終了したため、原典の国土数値情報と e-Stat を使う。人口は年次更新のため API キーを持たずビルド時の静的バンドルで足り、NF-04(オフライン耐性)とも整合する。プレゼン資料向けに試算した数値は `docs/flood-population.md`

## 5. 機能要件

データ取得の詳細(エンドポイント・フィールド・フィルタ)はすべて `docs/api-spec.md` に従う。

### F-01 地図画面(ホーム)

- ベースマップ上に各レイヤーを重ねて表示する。iOS 標準地図(react-native-maps / Apple Maps)を基本とし、API キー不要の構成とする
- 初期表示は直方市中心部(33.74, 130.73 付近)
- レイヤーの表示/非表示を切り替えられる
- **受入条件**: 起動から3秒以内に地図と避難所ピンが表示される(通常回線時)

**v1.6 拡張(地図の操作 UI)**: レイヤーの選択はチップの並びではなく、地図上の1つのボタンから開くシートに集める。シートは「いまの状況(ピン)」「塗り(1つ選ぶ)」「重ねる区域」「記憶」の4区分で、面の塗り(洪水浸水想定、地震のリスク、地形の分類、人口)は同時に1つしか選べない。凡例は塗りか区域があるときだけ1行で出し、展開できる。要約カードはたたんだ状態(1行)を既定にする。

- **受入条件(v1.6)**: 平常時の既定状態で地図が画面高の70%以上見える。塗りを切り替えると凡例と出典が追従する。塗りを選ぶと前の塗りが外れる

### F-02 避難所

- 全50件をピン表示。開設状況(`s_opening`)で色分け(閉鎖/開設・混雑度3段階)
- 詳細: 名称・住所・電話・収容人数・避難世帯数/避難者数・対応災害種別(水害/土砂/地震)
- 一覧表示(開設中を上位に)
- **受入条件**: ダッシュボードと同じ絞り込み(`s_opening <> '0'`)の「開設中リスト」が再現できる

**v1.6 拡張(対応災害の明示)**: 一覧の行は4種別すべてのタグを出し、非対応は灰色で示す。詳細シートは非対応の種別があるとき「地震のときは使えません」のように種別ごとに1行出す。熊本地震で指定避難所23か所が開設できなかった教訓による。

- **受入条件(v1.6)**: 地震に対応しない避難所の詳細に「地震のときは使えません」が出る

### F-03 水位センサー(20地点)

- 現在水位と警戒水位を表示し、水位/警戒水位の比率で色分け(正常/注意/危険)
- 詳細: 施設名・水位(cm)・警戒水位(cm)・計測日時(JST 表示)
- **リアルタイム性がデモの実証点**: 手動リフレッシュと画面復帰時の再取得を実装
- **受入条件**: デモ中に実データの `updateDt` が「数分前」であることを見せられる

### F-04 転倒ゲート(2地点)

- F-03 と同一 UI で表示(スキーマ共通)

### F-05 被害報告

- `field_7 = '公開'` のみをピン表示。災害状況種別で分類表示
- **取得フィールドは明示指定し、報告者氏名(`field_10`)・電話番号(`field_11`)は取得・表示・保存・ログ出力のいずれも行わない**(§7 NF-01)
- 平常時は0件のため、空状態 UI(「現在、公開されている被害情報はありません」)を必ず用意

### F-06 交通規制

- `openFlg = '公開'` のみを線表示。規制種別(一部/全面)で色分け、開始・解除日時と備考を表示
- 平常時0件の空状態 UI を用意

### F-07 ハザードマップ表示

- 重ねるハザードマップ配信タイルを地図にオーバーレイ表示(透過は固定値。調整 UI は将来検討)
- 対象レイヤーは市の Web 版ハザードマップと同じ構成とし、複数を同時に重ねられる(2026-07-15 拡張): 洪水浸水想定区域(想定最大規模)/土砂災害警戒区域(土石流)/土砂災害警戒区域(急傾斜地)/家屋倒壊等氾濫想定区域(氾濫流)
- 出典表記「ハザードマップポータルサイト(国土交通省)」を画面内に表示
- タイル URL・凡例色と浸水深ランクの対応は実装時に最新仕様を確認する

**v1.6 変更(土砂2区域の統合)**: 土石流と急傾斜地の警戒区域は「土砂災害の区域」として1つの切替で重ねる(2026-09-12 決定)。タイルは2種のまま、切替と凡例だけをまとめる。洪水浸水想定は塗り(F-01 拡張)の1つになり、地形分類、地震、人口とは切り替えて見比べる。

- **受入条件(v1.6)**: 切替1つで両区域が表示され、凡例に警戒区域と特別警戒区域が種別ごとに出る

### F-08 AR 浸水体験(本作品の核)

**最低ライン(3週目末までに完成)**:

- カメラ映像に対し平面検出(ARKit)で地面を認識し、指定高さに水面(半透明・濁り表現)を描画する
- 水面高さはスライダーで 0.5m〜5.0m の範囲で設定できる
- 現在の設定高さを「浸水深 ◯.◯m」として画面に明示する
- 地図画面のハザードマップ表示(F-07)から AR へ誘導する導線(「この深さを体感する」)を設ける

**ストレッチゴール(スケジュールに余裕がある場合のみ)**:

- 現在地の想定浸水深を重ねるハザードマップのタイル色から自動取得し、水面高さの初期値に設定する(「いまここは ◯m 沈む」)

**フォールバック(1週目の判断日で ViroReact が実機で動かない場合)**:

- 平面検出なしの簡易 AR(カメラ+ジャイロ追従の水平面)に切り替える

- **受入条件**: 屋外で起動し、30秒以内に水面が表示され、端末を動かしても水面が地面に張り付いて見えること(実機 iPhone で確認)

### F-09 デモモード

- データ取得層でライブ API とバンドル済み模擬データ(フィクスチャ)を切り替えられる
- 模擬シナリオは「大雨災害時の直方市」: 避難所複数開設(混雑度混在)・水位が警戒超過・公開被害報告・交通規制あり、の状態を再現する(シナリオ詳細は開発中に確定。2023年7月豪雨を参考にする)
- **ネットワークなしで全機能(AR 含む)が動作すること**(会場対策)
- 切り替えは設定画面の開発者向けトグルとする(一般利用者の誤操作を避けつつ、ブースで即座に切替可能)
- **受入条件**: 機内モードの実機で「平常時(キャッシュ)→デモモード(災害時)」の切替を10秒以内に実演できる

**v1.6 拡張(地震シナリオ)**: デモモードに地震シナリオを追加し、設定で大雨と切り替えられる。地震に対応しない避難所は閉鎖、対応する避難所は混雑3段階で開設、水位は平常、被害報告は瓦の落下、道路の段差、給水車の配置、橋梁の点検、ブロック塀の倒壊、交通規制は橋梁点検と路面の段差とする。すべて架空で、実在の施設名は使うが橋の名前は出さない。

- **受入条件(v1.6)**: 切替後10秒以内に、地震に対応しない避難所が閉鎖、対応する避難所が開設、水位が平常の状態で表示される。バナーにシナリオ名が出る

### F-10 川の防災情報リンクアウト

- 水位関連画面に「遠賀川の水位を見る(川の防災情報)」ボタンを設置し、外部ブラウザで kawabou のディープリンクを開く(`api-spec.md` §5)
- URL はハードコードせず設定値として一元管理する

### F-11 情報設計(将来のポータル化を前提)

- タブ構成は「ホーム(地図)/水位/避難所/その他」を基本とし、「その他」に AR・デモモード設定・アプリ情報・(将来: 生活機能)を収容する
- 文言・画面名に「防災アプリ」という自己定義を使わない(将来の生活ポータル化を妨げないため)

### F-12 じぶん設定(パーソナライズ)

アカウント登録ではなく、**端末内にのみ保存する設定**(§7 NF-07)。「登録」という言葉を UI で使わない。

**最低ライン(コンテスト版)**:

- 自宅(よく居る場所)を地図のピンで設定できる。住所のテキスト入力はさせない
- 設定すると: 避難所一覧が自宅からの直線距離順になり、ホーム要約カードに最寄り避難所(名称・距離)が出る
- 距離は端末内で計算(ハバサイン)。ArcGIS の空間クエリ(`geometry` + `distance`)で API 側に絞らせてもよい

**将来(ポータル版)**:

- 地区・校区の選択(通知対象の単位。通知はトピック購読方式とし、自宅位置をサーバに送らない)
- 世帯構成(高齢者・乳幼児・ペット等)→ 警戒レベル3(高齢者等避難)での行動提案、持ち物リストの出し分け
- 自宅地点の想定浸水深を AR(F-08)の初期値にする(タイル色読みのストレッチと同じ仕組み)

- **受入条件**: 自宅ピンを設定 → 避難所一覧が距離順に並び替わり、アプリ再起動後も設定が保持される。機内モードでも設定・並び替えが動作する

**v1.6 拡張(徒歩分数と災害種別ごとの最寄り)**: 距離に徒歩分数(80m/分、切り上げ、「約」つき)を添える。最寄り避難所は水害時と地震時で分けて出し、同じなら1行にまとめる。避難場所までの移動時間を知る人が34%しかいない調査結果(`docs/kumamoto-2026-lessons.md` §4)による。

- **受入条件(v1.6)**: 自宅ピンを置くと、要約カードに種別ごとの最寄り避難所と「徒歩 約◯分」が出る。一覧の行にも距離と徒歩分数が出る

### F-13 やさしい日本語モード

直方市の外国人住民は 2026-03 末で約1,030人(総人口の約1.9%)、前年から増加が続く(出典: 市の人口・世帯数統計)。
国籍は技能実習を中心に多国籍へ分散するため、複数言語の翻訳より、日本語1言語で全国籍をカバーする「やさしい日本語」を採る。
これは国(出入国在留管理庁・文化庁)が示す災害時コミュニケーションの基本方針に沿う。

**対象(コンテスト版。v1.3 で固定文言全般へ拡大)**:

- 設定に「やさしい日本語」トグルを追加する。端末内にのみ保存する(§7 NF-07)
- アプリ側が持つ固定文言を文言カタログに集約し、平易版へ切り替える。状態ラベル・タブ名・画面タイトル・ボタン・注意書き・エラー/空状態・AR 本体の案内文・アラートを含む
- 数値に添えるラベル語(「収容可能人数」「約」等)は対象。文の組み立て直しはしない
- ふりがなは自動付与せず、避けられない漢字に「漢字(かんじ)」形式で読みを添える

**含まない(将来要件)**:

- API 由来の動的テキスト(避難所名・河川名・被害報告や交通規制の自由記述)。固有名詞は原文のまま残す
- 数を数える文(「◯地点で警戒超過」「◯箇所 開設中」等)。語順と助数詞の組み替えは誤りが避難行動に直結するため、別途検討して段階的に広げる
- 出典表記・ハザードレイヤーの正式名称(凡例見出し)。情報の出所と法令上の区域名は原文の正確さを優先する(レイヤー選択チップの短い名前にはふりがなを添える)

- **受入条件**: トグルで切替でき、再起動後も保持される。切替時に対象画面の固定文言が平易版へ変わる。防災用語の意味が原文から変わらない(平易化で誤読・誤解を生まない)

### F-14 人口レイヤー(プロトタイプ)

プレゼンの課題設定「浸水想定区域に市民の4割が住む」(`docs/flood-population.md`)を地図でも見せるための機能。
提出締切(8/14)は ProtoPedia への作品情報掲載のみが必須で実装は本番まで継続できるため、8/9 の機能凍結の例外として 2026-08-11 に追加した。

- 国土数値情報 500mメッシュ別将来推計人口(R6国政局推計)を `scripts/flood-population.py` で直方市域に切り出し、静的 JSON(約28KB)としてバンドルする。API・キーを持たず、機内モード・デモモードでもそのまま動く(NF-04)
- ホーム(S-01)のレイヤーチップに「人口」を追加する(既定は非表示)。2025年推計の市内ぶん人口で 500m メッシュを主色の濃淡4段階に塗り分ける(状態色・ハザードタイルと別色相)
- メッシュをタップすると「◯◯ 付近 約◯人(65歳以上 約◯人)」を詳細シートで表示する(按分値のため10人単位に丸める)。地域名は国勢調査 小地域境界(e-Stat)との突合でセルと最も広く重なる町丁字を代表にする
- 凡例と出典表記(国土数値情報)を地図上に表示し、設定画面の出典にも明記する(NF-06)

- **受入条件**: レイヤーを点けると塗り分けと凡例が出て、タップで人数が表示される。機内モードでも動作する。土砂災害と家屋倒壊の区域と同時に重ねても区域の色が判読できる(v1.6 で塗りは1つに限るため、洪水浸水想定とは切り替えて見比べる。v1.5 の「ハザードレイヤーと同時に重ねても」は v1.6 で置き換えた)

### F-15 地震ハザードレイヤー(v1.6)

令和8年熊本地震の教訓を「自分の場所の数字」にするための機能。
直方市には地震のハザードマップがなく、市域を通る福智山断層帯(M7.2 程度、30年以内の発生確率ほぼ0〜3%)の揺れやすさを市民が見る手段がない。
J-SHIS(防災科研)の 250m メッシュを市域ぶん取り出したところ、30年以内に震度6弱以上となる確率は市内7地点で 0.6% から 9.5% まで開きがあり、表層地盤で説明できる(`docs/quake-ground-layers.md` §2)。

- J-SHIS の地震ハザード情報 API(2024年基準 NIED 作成版)と表層地盤情報 API から、30年以内に震度5強以上、6弱以上、6強以上となる確率、計測震度、微地形区分、増幅率を市域の 250m メッシュぶん取り出し、ビルド時に静的 JSON として同梱する(実行時に API を呼ばない。NF-04)
- 塗りは地震本部の5段階(0.1% 未満、0.1〜3%、3〜6%、6〜26%、26% 以上)。描画は区分ごとに融合した多角形で行い、タップは座標からメッシュコードを計算して値を引く
- 福智山断層帯の断層モデルの上端を線で示し、凡例にその旨を書く
- タップした地点の詳細シートに、確率3値、微地形区分、増幅率、注意書き「確率は相対的な目安で、安全度ではなく危険度を示す」、出典を出す
- 出典表記は「J-SHIS 地震ハザードステーション(防災科学技術研究所)2024年基準 NIED作成版を加工して作成」とし、地震本部の公式地図と混同させない

- **受入条件**: 塗りを「地震のリスク」にすると塗り分けと凡例が出て、タップで「今後30年に震度6弱以上 ◯%、地盤 ◯◯」が出る。凡例に注意書きがある。機内モードで動く

### F-16 地形分類レイヤー(v1.6)

令和8年8月千葉豪雨で浸水被害の 55.7% が浸水想定区域の外で起きた教訓(内水氾濫)と、直方市の近年の浸水が本川の氾濫ではなく支川と低地の内水で起きている事実(`docs/nogata-disaster-history.md` §4.1)に対し、「川と関係なく水が溜まりやすい土地」を示す。

- 国土地理院の治水地形分類図(更新版)を地理院タイルで塗りの1つとして重ねる。ズーム 11〜16
- 凡例は山地、段丘面、氾濫平野、後背湿地、微高地(自然堤防)、旧河道、盛土地・埋立地、現河道・水面の8分類に絞り、「山地側は範囲外(空白は安全の意味ではない)」の注記を出す
- 出典表記は「国土地理院(治水地形分類図)」。明治期の低湿地は市の南半分が未整備のため使わない

- **受入条件**: 塗りを「地形の分類」にすると凡例8分類と注記が出る。設定画面の出典に国土地理院が載る

### F-17 自然災害伝承碑(v1.6)

直方市に登録された自然災害伝承碑は、植木の記念碑(昭和28年西日本水害の決壊)と殿町の遠賀川改修記念碑(明治38年の洪水)の2基である。
過去の被災を地図の上で読めるようにし、平時にアプリを開く理由の1つにする。

- 国土地理院の伝承碑データ(GeoJSON、2026-08-27版)から直方市の碑をビルド時に取り出して同梱する
- 地図に専用のピンで示し、タップで碑名、災害名、建立年、伝承内容(原文のまま)、所在地、出典を出す。写真は扱わない
- 「記憶」の切替で表示を制御し、既定は表示

- **受入条件**: 2基のピンが地図に出て、タップで碑名、災害名、建立年、伝承内容が出る

### F-18 公式情報への導線(v1.6)

熊本地震では偽の救助要請や偽動画が拡散し、被災自治体の公式 LINE が障害で第一報を出せなかった。
一次情報への入口を1画面にまとめ、共有前の確認を促す。

- その他タブから開く画面に、直方市の緊急情報、福岡県防災ホームページの直方市避難情報、気象庁の警報、川の防災情報、災害用伝言ダイヤル 171 と web171、00000JAPAN(既存画面)へのリンクを置く。すべてリンクアウトで、データ取得はしない
- 冒頭に「災害のときは根拠のない情報が広まります。共有する前に、発信元が公式か確かめてください」の注意書きを置く
- URL は1箇所の定数に集める。確認できない URL は載せない

- **受入条件**: その他タブから1タップで開き、各リンクが外部ブラウザまたは電話アプリを起動する

## 7. 非機能要件

### NF-01 個人情報の排除(最重要)

- ArcGIS への全クエリで `outFields` を明示指定する。`field_10`・`field_11`・`Creator`・`Editor`・`input_p`・`input_tel` は指定禁止
- 実装は許可フィールドのホワイトリストを一箇所で管理し、コードレビュー/テストで担保する

### NF-02 読み取り専用・公開フラグの尊重

- ArcGIS への書き込み系リクエスト(addFeatures 等)を発行しない
- ダッシュボードと同一の公開フィルタ(`field_7='公開'`、`openFlg='公開'`)を必ず適用する

### NF-03 取得ポリシー

- ポーリングは行わず、画面表示時+手動リフレッシュ+フォアグラウンド復帰時に取得。同一データの再取得は最短60秒に制限(市の共有インフラへの配慮)
- タイムアウト・失敗時はキャッシュ表示+エラーバナー(アプリを止めない)

### NF-04 オフライン耐性(デモ要件)

- 最終取得データをローカルキャッシュし、オフライン時はキャッシュ+取得時刻を表示
- デモモードは完全オフラインで動作(F-09)

### NF-05 表示・品質

- 日時はすべて JST で「◯月◯日 ◯:◯ 時点」形式
- コード値(開設状況等)は日本語ラベルに変換して表示(`api-spec.md` のドメイン定義に従う)
- 空状態・エラー状態・読込中状態を全画面で設計する(平常時は空データが正常系)

### NF-06 出典・免責

- 設定画面に出典(直方市 災害時情報共有PF / ハザードマップポータルサイト(国土交通省))と免責(本アプリは非公式であり、避難判断は市の公式情報に従うこと)を明記

### NF-07 個人情報は端末から出さない(設計原則)

- じぶん設定(自宅ピン・地区・世帯構成)は端末内(AsyncStorage/MMKV)にのみ保存し、いかなるサーバにも送信しない
- アカウント・ログインを作らない。将来プッシュ通知を導入する際も、トピック購読方式(端末が「地区X の通知」を購読する)とし、サーバが自宅位置・住所を保持しない構成を維持する
- この原則は市への説明材料でもある(個人情報を扱わない設計を対外的に示せる)
