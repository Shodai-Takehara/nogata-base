# 直方市 災害時情報共有PF データAPI仕様書

直方市の ArcGIS Online ダッシュボード「災害時情報共有PF（公開用）」が参照するデータソースの仕様をまとめたもの。モバイルアプリのデータ取得層の実装を目的とする。

- 調査日: 2026-07-13
- 元ダッシュボード: <https://nogata.maps.arcgis.com/apps/dashboards/a7e176b0dd544aa4a30551d31890664a>
- ダッシュボードアイテムID: `a7e176b0dd544aa4a30551d31890664a`（access: public）
- 参照Webマップ「市民公開用マップ」: `1d74495fd8cb493497639699a66fd625`（access: public）
- データ所有者: 直方市（ArcGIS Online アカウント `n_saigai_PF`）

> **重要**: これは直方市が「アプリ開発者向けに提供している公開API」ではなく、公開設定された ArcGIS Feature Service を REST API として読んでいるもの。市側の設定変更で予告なく非公開化・URL変更されうる。公式アプリとして公開する場合は市への利用確認を推奨。**書き込み系操作（addFeatures / updateFeatures 等）は行わないこと。**

## 1. 共通仕様

### ベースURL

```text
https://services1.arcgis.com/Po7csFzrJvObgZNq/arcgis/rest/services/{サービス名}/FeatureServer/0
```

### 認証

不要（匿名アクセス可）。APIキー・トークン不要。

### データ取得エンドポイント

```text
GET {ベースURL}/query
```

主なクエリパラメータ:

| パラメータ                                     | 説明                                       | 例                 |
| ---------------------------------------------- | ------------------------------------------ | ------------------ |
| `where`                                        | SQL風フィルタ（必須。全件は `1=1`）        | `s_opening <> '0'` |
| `outFields`                                    | 取得フィールド（カンマ区切り、`*` で全件） | `s_name,s_opening` |
| `f`                                            | レスポンス形式: `json` / `geojson` / `pbf` | `geojson`          |
| `outSR`                                        | 出力座標系（`4326` 推奨）                  | `4326`             |
| `resultOffset` / `resultRecordCount`           | ページネーション                           | `0` / `100`        |
| `orderByFields`                                | ソート                                     | `updateDt DESC`    |
| `returnCountOnly`                              | 件数のみ取得                               | `true`             |
| `outStatistics` / `groupByFieldsForStatistics` | 集計                                       | count 等           |
| `returnGeometry`                               | ジオメトリ省略で軽量化                     | `false`            |

- 全レイヤーで `maxRecordCount = 2000`、ページネーション対応（`supportsPagination: true`）。
- レスポンスに `"exceededTransferLimit": true` が含まれたら `resultOffset` を進めて続きを取得する。
- 対応形式は全レイヤー共通で JSON / GeoJSON / PBF。

### 日時・座標の扱い

- **日付フィールド（esriFieldTypeDate）はすべて UNIXエポックミリ秒**（例: `1783919558000`）。タイムゾーンはUTC基準のエポックなので、表示時に JST 変換する。
- 座標系はレイヤーごとにバラバラ（JGD2011 平面直角系 / wkid 104020 / WGS84）。**`f=geojson` または `outSR=4326` を指定すれば常に WGS84 経緯度で受け取れる**ので、アプリ側は常にこれを指定すること。

### エラーレスポンス

HTTPステータスは200のまま、ボディにエラーが入る形式:

```json
{"error": {"code": 400, "message": "...", "details": [...]}}
```

`error.code` の有無で成否判定すること。

## 3. ダッシュボードのウィジェット再現マッピング

モバイルアプリで元ダッシュボードと同じ表示を作る場合の対応表。

| ダッシュボード要素 | レイヤー                                     | フィルタ             | 表示内容                                                                    |
| ------------------ | -------------------------------------------- | -------------------- | --------------------------------------------------------------------------- |
| 開設避難所リスト   | refuges                                      | `s_opening <> '0'`   | `{s_opening}` `{s_name}`（`{n_family}`世帯・`{n_refugees}`人が避難中）      |
| 市内の被害（件数） | survey123                                    | `field_7 = '公開'`   | `count(objectid)` 件                                                        |
| 交通規制（件数）   | traffic_reguration                           | `openFlg = '公開'`   | `count(OBJECTID)` 箇所                                                      |

## 4. 実装上の注意

1. **読み取り専用で使うこと。** サービスの capabilities に `Update` / `Editing`（survey123 と traffic_reguration は `Create` / `Delete` も）が含まれているが、これは市の内部運用（Survey123 / 職員編集）用。書き込み系エンドポイントは呼ばない。survey123 レイヤーは匿名の更新・削除が明示的に無効化されているが、他レイヤーも含め一切試みないこと。
2. **公開フラグの尊重。** 非公開レコードも技術的には取得できるが、アプリではダッシュボードと同じフィルタ（`field_7='公開'`、`openFlg='公開'`、`s_opening` 等）を必ず適用し、市が非公開としているデータを表示しない。
3. **平常時はデータが少ない。** 被害報告・交通規制の「公開」件数は平常時0件。空状態のUIを設計しておく。水位センサー・転倒ゲートは平常時も更新され続けるので、アプリの疎通確認・鮮度表示にはこれを使うとよい。
4. **ポーリング間隔は控えめに。** 元ダッシュボードにもリアルタイムpushはなく、ポーリング相当。センサー系は1〜10分間隔、マスタ系（避難所位置等）はアプリ起動時＋長めのキャッシュで十分。自治体の共有インフラなので過剰リクエストは避ける。
5. **サービス消失への備え。** 市側の都合で非公開化・スキーマ変更されうる。エラー時のフォールバック表示と、フィールド名のハードコードを1箇所に集約する設計を推奨。
6. **ベースマップ。** Webマップは背景図として ArcGIS Online のアイテム（`73b77bc7...` ほか）を参照している。モバイルアプリでは OpenStreetMap や地理院タイルなど自前のベースマップを使う方がライセンス的に簡明。

## 5. 外部連携：川の防災情報（国交省）— リンクアウト方式

遠賀川本川の水位・洪水予報など「川の防災情報」相当の情報は、**アプリ内にデータとして取り込まず、該当ページを外部ブラウザ（または WebView）で開くリンクアウト方式**とする。

背景: `www.river.go.jp`（川の防災情報）・`www1.river.go.jp`（水文水質データベース）はプログラムからのアクセスが 403 Forbidden となり、「This site prohibits data acquisition using tools, etc.（ツール等によるデータ取得禁止）」と明示されている（調査日: 2026-07-13）。サイト内部 API をアプリのデータソースにすることはできないが、ページへのリンクは禁止されていない。

なお、気象庁の防災情報 JSON（警報・指定河川洪水予報等）を代わりに取り込む案は採用しない。サイト内部用の非公式エンドポイントであり、外部利用の保証がなくパス・スキーマが予告なく変わりうるため、防災情報の供給路としては現実的でない。

### リンク先（市町村ページに1本）

観測所を個別にリンクすると、選定・URL 調査・国交省側の改修への追従が観測所の数だけ増える。市町村コードで直方市に絞った観測所一覧ページ1本にして、追従点を1箇所へ集約する。

```text
https://www.river.go.jp/index/twninfo/pc?prefCd=4001&twnCd=4001204&type=obs&tm=stg
```

| パラメータ | 意味（URL からの推定を含む）       |
| ---------- | ---------------------------------- |
| `prefCd`   | 都道府県コード（`4001` = 福岡）    |
| `twnCd`    | 市町村コード（`4001204` = 直方市） |
| `type`     | 表示種別（`obs` = 観測所）         |
| `tm`       | 観測項目（`stg` = 水位）           |

- パラメータの正確な意味は公開されていないため、**実際にブラウザで目的の表示にした状態の URL をそのままコピーして使う**のが確実。
- URL 仕様は国交省側の改修で変わりうるため、リンク URL はハードコードせず設定値（`src/constants/links.ts` に集約。将来は Remote Config 等）で持ち、1箇所の変更で差し替えられるようにする。

### 実装イメージ

- 水位画面（§2.2）や地図の要約に「直方市の川の水位（川の防災情報）」ボタンを置き、外部ブラウザで開く。
- WebView 内表示にする場合も「ページをそのまま表示」するだけとし、WebView 経由でのデータ抽出・加工は行わない。

## 6. 地震ハザード：J-SHIS 地震ハザードステーション（防災科学技術研究所）— ビルド時に静的化

地震ハザードレイヤー（要件 F-15）は、J-SHIS の API から直方市域ぶんの 250m メッシュを取り出し、`scripts/quake-hazard.py` で `src/constants/quake-mesh.json` に静的化して同梱する（調査日: 2026-09-12、API から値を取った日はファイルの `meta.fetchedAt`。キャッシュから再生成しても変わらない）。
アプリの実行時にはこの API を呼ばない（要件 NF-04）。

### 使う API

| 用途                       | エンドポイント                                                                    | 取り出す属性                                                       |
| -------------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 確率論的地震動予測地図     | `https://www.j-shis.bosai.go.jp/map/api/pshm/Y2024/AVR/TTL_MTTL/meshinfo.geojson` | `meshcode`、`T30_I50_PS`、`T30_I55_PS`、`T30_I60_PS`、`T30_P03_SI` |
| 表層地盤                   | `https://www.j-shis.bosai.go.jp/map/api/sstrct/V4/meshinfo.geojson`               | `meshcode`、`JCODE`、`JNAME`、`ARV`                                |
| 断層モデル（福智山断層帯） | `https://www.j-shis.bosai.go.jp/map/api/pshm/Y2024/AVR/F012101/fltinfo.geojson`   | 矩形の上端2点（深さ 3km）、走向、傾斜、長さ、幅                    |

- 共通のクエリは `?position={lng},{lat}&epsg=4326`。その座標を含む 250m メッシュ1件が `features[0]` に返る。`epsg` を省くと `INVALID_REQUEST` になる
- 属性値はすべて文字列で返る（例: `"T30_I55_PS": "0.095169"`）。数値に変換して使う
- `T30_I55_PS` は「今後30年間に震度6弱以上の揺れに見舞われる確率」、`T30_I50_PS` と `T30_I60_PS` は同じく震度5強以上と6強以上、`T30_P03_SI` は 30年超過確率3%の計測震度。`ARV` は表層地盤の増幅率、`JCODE` と `JNAME` は微地形区分のコードと名称
- 年版は `Y2024` が最新（`Y2025` は 400 を返す）。地図の凡例には「2024年基準」と書く
- 呼び出し上限は公表されていない（403 がエラーコードとして定義されている）。生成スクリプトは 1件ずつ 200ms 空け、403 なら 60秒待って再試行し、応答を `.cache/quake-hazard/` に保存して再実行時は呼ばない
- 上限に当たり続けるときは、ダウンロードページ（<https://www.j-shis.bosai.go.jp/download>）の1次メッシュ 5030 の CSV を `--csv` で読ませる経路を用意している。CSV の列名は API と同じと仮定しており、未検証

### メッシュコード

250m メッシュのコードは JIS X 0410 の区画方式（3次メッシュ 1/120°×1/80° を 2×2 に分けた 500m 区画に、さらに 2×2 の 250m 区画）で、座標から計算できる。
アプリ側は `src/utils/mesh-code.ts` で座標からコードを求め、`quake-mesh.json` の `cells` を引く（生成スクリプトの `mesh_code_250` と同じ式）。

**座標 → コード（10桁）**。緯度 `lat`、経度 `lng`（10進の度、WGS84）に対して、次の順に整数部を取り出す。`floor` は切り捨て。

| 桁   | 意味                      | 式                                                         |
| ---- | ------------------------- | ---------------------------------------------------------- |
| 1〜2 | 1次メッシュ（緯度）       | `p = floor(lat × 1.5)`                                     |
| 3〜4 | 1次メッシュ（経度）       | `u = floor(lng − 100)`                                     |
| 5    | 2次メッシュ（緯度、0〜7） | `q = floor(a × 8)`、ただし `a = lat × 1.5 − p`             |
| 6    | 2次メッシュ（経度、0〜7） | `v = floor(b × 8)`、ただし `b = lng − 100 − u`             |
| 7    | 3次メッシュ（緯度、0〜9） | `r = floor(a′ × 10)`、ただし `a′ = a × 8 − q`              |
| 8    | 3次メッシュ（経度、0〜9） | `w = floor(b′ × 10)`、ただし `b′ = b × 8 − v`              |
| 9    | 500m 区画（1〜4）         | `a″ = a′ × 10 − r`、`b″ = b′ × 10 − w` から `区画(a″, b″)` |
| 10   | 250m 区画（1〜4）         | `区画((a″ × 2) mod 1, (b″ × 2) mod 1)`                     |

区画番号は `区画(緯度の端数, 経度の端数) = (端数の緯度 < 0.5 なら 1、それ以外は 3) + (端数の経度 < 0.5 なら 0、それ以外は 1)`、つまり南西 1、南東 2、北西 3、北東 4。
500m メッシュのコード（`--mesh 500`）は上 9 桁。

**コード → 矩形**。南西隅は次の式で、北東隅は緯度 `1/480°`、経度 `1/320°` を足す（500m は `1/240°`、`1/160°`）。

```text
lat = p / 1.5 + q / 12 + r / 120 + (500m 区画が 3 か 4 なら 0.5) / 120 + (250m 区画が 3 か 4 なら 0.5) / 240
lng = 100 + u + v / 8 + w / 80 + (500m 区画が 2 か 4 なら 0.5) / 80 + (250m 区画が 2 か 4 なら 0.5) / 160
```

### 生成の手順と計算

1. 国土数値情報 N03（2025）の直方市の行政区域（`scripts/flood-population.py` と同じキャッシュ）の外接矩形を 250m メッシュで覆い、市域と面積を持って重なるメッシュ（1,025 枚）を残す。辺で接するだけのメッシュは除く
2. 各メッシュの中心座標で 2 つの API を呼び、`meshcode`、確率 3 値、計測震度、微地形区分、増幅率を取る。API が返した `meshcode` が計算したコードと違えば止める
3. 値は API の精度のまま持つ（確率は小数 6 桁、増幅率は小数 2 桁、計測震度は小数 1 桁）。**丸めない**。小数 3 桁に丸めてから区分すると、境界のすぐ下のメッシュ（2.9956% など 7 枚）が J-SHIS の地図より 1 段濃い区分に入る
4. 区分は `p55`（今後 30 年に震度 6 弱以上）を境界 `0.001、0.03、0.06、0.26` で 5 段階に分ける。境界の値は上の区分に入る（`p55 ≥ 0.03` なら「3〜6%」）。アプリの `quakeBucket` も同じ境界と比較で、同梱値からそのまま区分を引く
5. 区分ごとに、市域で切ったメッシュの矩形を shapely の `unary_union` で融合し、外周と穴（別の区分に囲まれた部分）に分けて書く。座標は小数 5 桁（約 1m）に丸め、丸めで同じになった隣の頂点は 1 つにする
6. `--mesh 500` のときは、同じ 500m 区画の 4 枚を集約してから 4 と 5 を行う。確率、計測震度、増幅率は市内ぶんの面積で重み付けした平均（`Σ 値 × 面積 ÷ Σ 面積`）、微地形区分は面積の最も大きいもの。平均は目安であり、詳細シートにはその旨を注記する

表示側の計算は次の 2 つだけ。

- 確率の表示は `p × 100` を小数 1 桁に四捨五入（`toFixed(1)`）。区分は丸める前の値で決めるので、2.9956% は「3.0%」と出ても区分は「0.1〜3%」
- 増幅率は小数 2 桁（API の精度のまま）

### 微地形区分の説明の根拠

詳細シートの地盤の ⓘ で出す説明（`JNAME_NOTE`）は、次の 2 つから書き起こした。

- 土地の成り立ちと土質: 若松加寿江・松岡昌志「全国を網羅した地形・地盤分類250mメッシュマップの構築」表1 地形分類コードと分類基準（<https://www.chika-db.bosai.go.jp/event090306/pdf/03wakamatsu.pdf>）。J-SHIS の微地形区分はこの分類（2020 年更新版）による
- 液状化のしやすさ: 国土交通省「地形区分に基づく液状化の発生傾向」の 5 段階（<https://www.mlit.go.jp/toshi/content/001388130.pdf>）。市域に現れる 8 区分は、旧河道・旧池沼（最も強い）、自然堤防（2 段目）を「しやすい」、後背湿地・谷底低地・河原（3〜4 段目。谷底低地と河原は傾斜で変わる）を「可能性がある」、山地・丘陵・砂礫質台地（最も弱い）を「しにくい」と書いた

揺れの増幅の大小は土質の軟らかさからの傾向で、セルごとの実際の値は API の `ARV` を出している。

J-SHIS の利用規約（<https://www.j-shis.bosai.go.jp/agreement>）は、出典を明示すれば加工と再配布ができ、そのままの複製配布は不可、販売は申請が要る場合があるとしている。
アプリは市域ぶんに切り出して融合した「加工物」を同梱するため、出典表記を次の形で必ず出す（NF-06）。

```text
出典: J-SHIS 地震ハザードステーション(防災科学技術研究所)2024年基準 NIED作成版を加工して作成
```

### 生成物の形

```json
{
  "meta": {
    "version": "Y2024",
    "fetchedAt": "2026-09-12",
    "cells": 1025,
    "mesh": 250
  },
  "cells": {
    "5030458834": {
      "p50": 0.389915,
      "p55": 0.095169,
      "p60": 0.020773,
      "si": 5.8,
      "arv": 1.84,
      "jcode": 12,
      "jname": "自然堤防"
    }
  },
  "classes": [
    {
      "bucket": 3,
      "polys": [
        {
          "outer": [
            [130.73, 33.74],
            [130.73, 33.742]
          ],
          "holes": []
        }
      ]
    }
  ]
}
```

- `cells` はメッシュコードで引く辞書で、形状を持たない（矩形はコードから復元する）。値は API の精度のままで丸めていない
- `classes` は地震本部の5段階（`p55` が 0.1% 未満、0.1〜3%、3〜6%、6〜26%、26% 以上）ごとに市域で切ったメッシュを融合した多角形で、塗りに使う。座標は `[lng, lat]`。`holes` は別の区分に囲まれた部分で、`Polygon` の `holes` に渡す（穴を空けないと内側の区分の塗りと重なって濃く見える）
- `--mesh 500` で集約したときは `meta.mesh` が 500 になり、`cells` のキーは9桁（500m メッシュ）になる。アプリ側は `meshCodeAt(lat, lng, QUAKE_META.mesh)` で引く
- 融合面の頂点を間引く選択肢は持たない。区分ごとに別々に間引くと隣り合う区分の共有辺がずれて隙間と重なりができ、頂点は 3,000 弱で間引く必要もないため
- 生成物は 170KB 前後（整形前）。リポジトリには Prettier で整形した状態で入るため 280KB 前後になるが、バンドルには影響しない

## 7. 地形分類：治水地形分類図（国土地理院）— 地理院タイルをそのまま重ねる

地形分類レイヤーは、国土地理院の治水地形分類図（更新版）を地理院タイルとして地図に重ねる（調査日: 2026-09-13）。
ハザードマップポータルのタイルと同じく、アプリは配信元のタイルをそのまま描き、加工物を持たない。

### 配信仕様

| 項目       | 値                                                                                                                             |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------ |
| URL        | `https://cyberjapandata.gsi.go.jp/xyz/lcmfc2/{z}/{x}/{y}.png`                                                                  |
| ズーム     | 11〜16（地理院タイル一覧の記載。範囲外は 404。アプリは 16 より拡大したとき 16 のタイルを切り出して拡大する）                   |

| 一覧・凡例 | <https://maps.gsi.go.jp/development/ichiran.html#lcmfc2>、<https://cyberjapandata.gsi.go.jp/legend/lcmfc2_legend.jpg>          |

- タイルには基図の地名、建物、地盤高線の数字も入っている。ズームを上げるほど文字が増えるので、透過度は 0.7（ポータルのタイル）より下げて 0.5 を候補にした。実機で地名が読めなければさらに下げる

### 凡例の色の抽出

凡例の色見本は、公式の凡例画像ではなくタイルの実画素から取る。
タイルは分類の色を基図の上に透かして描いているため、公式の色より白寄りになり、公式の色を見本にすると地図と見本が合わない。

手順（2026-09-13、`node` と `pngjs` で実施）。

1. 市域の z16 タイル 481 枚の全画素を色ごとに数える
2. 出現割合 0.1% 以上の色を、公式の解説ページの色見本画像（PNG）の色と突き合わせる。単色で塗られる区分のうち山地、段丘面、氾濫平野、後背湿地、微高地（自然堤防）の 5 つ（凡例に入れなかった山麓堆積地形と崖を含めると 7 つ）は「公式の色 × 0.65 + 白 × 0.35」（小数第2位まで）で誤差 2/255 以内に一致した。現河道・水面はこの式に合わない（基図側にも水面の色があるためとみられる）ので、観測した色をそのまま使う。縞の区分と切土地は次の手順と本文のとおり別に読む
3. 縞模様の区分（旧河道、盛土地・埋立地）は z16 のタイルを拡大して、地の色と縞の色を別々に読む

| 区分               | 公式の色（解説ページ）    | タイルの色                        | z16 での出現割合 |
| ------------------ | ------------------------- | --------------------------------- | ---------------- |
| 山地               | `#FFD481`                 | `#FFE3AC`                         | 14.8%            |
| 段丘面             | `#FFAA01`                 | `#FFC85A`                         | 3.0%             |

### 表示側の扱い

- レイヤー定義（`src/constants/hazard-map.ts` の `landform`）はズーム 11〜16 と透過度 0.5 を持ち、`tileOptions()` が `UrlTile` の値を組み立てる。省略した項目はポータルのタイルの共通値（ズーム 2〜17、透過度 0.7）で埋める。上限ズームは `maximumZ` でなく `maximumNativeZ` として渡す。`maximumZ` だとそれより拡大したとき塗りが消えて凡例だけが残る（ポータルのタイルも同じ扱いにしたので、洪水も 17 より拡大したとき消えなくなった）
- 塗りの 1 つとして排他で出す。洪水浸水想定と同時には出せないが、両方を重ねると色が混ざって判読できないため切り替えて見比べる形にした。人口メッシュとも同時に出さない。図郭の内側は白い基図まで不透明に描かれるので、下にある人口の青が半分の濃さになったうえに塗りの色と混ざり、どちらの段階も見本と合わせられない
- 凡例ストリップ（地図上の帯）では 9 区分の色見本だけを並べ、区分名はレイヤー選択シートで読ませる。縞の区分は見本にも横縞を描く
- シートの凡例では各区分の横の ⓘ から一言（「わずかな雨でも浸水しやすく、深く長く続く」など）を吹き出しで出す。区分名の下に並べるとシートの縦幅を取りすぎる。区分名だけでは、どの土地に水が溜まりやすいのか読めないため。文は国土地理院「治水地形分類図の内容」（<https://www.gsi.go.jp/bousaichiri/bousaichiri41051.html>）の各区分の「防災上の留意点」から起こし、平易版も持つ

## 9. 避難所までの道のり：OpenStreetMap の道路 — ビルド時に静的化

自宅から避難所までの距離と徒歩分数は、直線距離ではなく歩ける道をたどった最短経路（道のり）で出す。
直方は遠賀川が市の中央を南北に流れ、渡れる橋が限られるため、直線だと対岸の避難所が「最寄り」になり、分数も実際の半分ほどに出る（2026-09-14 の検証: 遠賀川の東岸(溝堀)から対岸の遠賀川水辺館は直線 353m に対し道のり 850m、下境から直方第一中学校は 184m に対し 904m）。
道路は OpenStreetMap から直方市域ぶんを `scripts/walk-graph.py` で取り出し、`src/constants/walk-graph.json` に静的化して同梱する。端末内で最短経路を引くので通信は要らず、デモモードでも動く。

### 取得元

| 項目     | 値                                                                                                                                                                                                                                      |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| API      | Overpass API `https://overpass-api.de/api/interpreter`（POST、`data` に Overpass QL）。応答は `.cache/walk-graph/overpass.json` に保存し再利用する                                                                                      |
| 範囲     | 市域の外接矩形（緯度 33.700〜33.796、経度 130.680〜130.806）に約 500m（0.005 度）の余裕。市境をまたいで戻る道のため                                                                                                                     |
| 取る道   | `highway` を持つ way のうち歩ける種類（`footway`、`path`、`residential`、`unclassified`、`tertiary`、`primary`、`trunk`、`service`、`track` など）。`motorway`、工事中は除く。`foot=no`、`access=no/private`（`foot=yes` でない）は除く |
| 利用条件 | ODbL。出典表記「© OpenStreetMap contributors」を出典カードに出す                                                                                                                                                                        |
| UA       | Overpass は既定の Python の UA を 406 で断るため、スクリプト名を入れた User-Agent を送る                                                                                                                                                |

### 取り出し方

- 道の折れ点をすべて節にした生のグラフ（約 5.3 万節、塊 9 つ）から最大の塊（5.3 万節）だけ残し、交差点と行き止まり（次数が 2 でない節）の間の道を 1 本ずつ取り出す
- 各道の曲がり角を Douglas-Peucker（許容 5m）で間引く。**区間の長さは間引く前の折れ点をすべて足した実長**で持つので、道のりは間引きで短くならない。間引くのは自宅や避難所を道に落とすための形だけ
- 生成物は約 2.2 万節、2.7 万辺、385KB。値は前の値との差で持ち、節の番号は道なりに続く節が隣り合うよう辺を出した順に振る

### 生成物の形

```json
{
  "meta": {
    "source": "OpenStreetMap",
    "license": "ODbL",
    "fetchedAt": "2026-09-14",
    "origin": { "latitude": 33.695, "longitude": 130.675 },
    "quant": 1e-5
  },
  "nodes": [dlat, dlng, ...],
  "edges": [da, db, len, ...]
}
```

- `nodes`: 節の座標。`origin` からの `quant` 度（約 1m）単位の整数を、前の節との差で並べる
- `edges`: 辺。`a` は前の辺の `a` との差、`b` は `a` との差、`len` は実長（m）。`a` の昇順

### 端末での計算（`src/utils/walk-route.ts`）

- 初めて道のりが要るとき（自宅ピンの設定後）に JSON を読み、平面（m）の座標と隣接（CSR）と、辺を 150m の升目に振った索引を作る
- 点を道に落とす: 周囲 300m の升目に掛かる辺だけを見て最も近い辺へ垂線を下ろす。道までが 300m を超える点は「落とせない」（市域の外や山の中）
- 自宅から Dijkstra を 1 回引き、避難所ごとに落とした辺の両端からの距離の短い方に、道までの直線を足す。自宅と同じ辺に落ちる避難所は直線で見る
- 自宅が道に落とせない、または道がつながっていない避難所は、直線距離に切り替えて「直線」と明示する
- 費用: 初回 33ms、以降 5ms（Node(JIT あり)での計測。自宅から 50 か所。JIT の無い Hermes ではおよそ 2〜5 倍とみる。実機の値は計測して足す）。自宅と避難所の座標が同じなら結果を使い回す（ホームと一覧が別々に取り直したデータで同じ計算をしない）

### 表示側の扱い

- 「道のり 約 650m・徒歩 8分以上」「直線距離 約 610m・徒歩 7分以上」。道のりか直線かを必ず添え、分数は「以上」にする。最短経路を速めの歩き（80m/分）で割って切り捨てた下限（80m 未満は 1 分、90 分で頭打ち）で、坂、夜、災害時の通行止めでは必ず長くなるため
- 一覧の並び、要約の最寄り（水害時・地震時）も道のりで決める。直線で補った避難所は道のりのある避難所の後ろに置く（直線は道のりより必ず短く出るので、最寄りに見せない）
- 道の塊は最大のものだけ同梱する。外接矩形で切った端の道は矩形の外で本体とつながっていて、中では飛び地になる。飛び地に自宅を落とすとどの避難所にも道が引けない
- 河川敷の遊歩道や自転車道、渡り橋も歩ける道に入る。洪水時に最初に使えなくなる道だが、市街地の自宅からの経路は渡り橋の有無で変わらず、表示は下限（以上）なので許容する。外すなら `natural=water` の内側の節を落とす（判断日ルールに従う）
- 生成時に避難所マスタの全施設が道から 150m 以内にあることを確かめる。Overpass が `remark` 付きの不完全な応答（時間切れ）を返したときは保存せず止める
