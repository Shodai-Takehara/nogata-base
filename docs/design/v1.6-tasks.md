**PR タイトル案**: `feat(map): レイヤー選択をボトムシートに集約し、地図の表示領域を広げる`

**設計**: `v1.6-design.md` §3.9、§3.2(型変更のうち `attribution` 以外は T4)

**変更ファイル**

**手順**

1. reducer と既定値を書き、テストを先に通す(UI に触れる前に状態の仕様を固める)
2. `MapBottomSheet` を作り、既存の要約カードを peek と要約の2状態で載せる。まだレイヤー選択は無し。実機で peek の高さと地図の可視領域を測る(画面高の70%以上)
3. `LayerPicker` と `LayersButton` を作り、既存7レイヤー(ピン5、塗り2、区域2)を移す。チップ行と下部パネルを消す
4. `LegendStrip` を作り、洪水、人口、区域の凡例と出典を出す。`FLOOD_ATTRIBUTION` と `POPULATION_ATTRIBUTION` はそのまま使う
5. 描画順を塗り → 区域タイル → ピンに並べ直し、区域タイルの `key` に `fill` を含める。人口とハザードを互いの `key` に入れる既存の制御を外す
6. その他タブの「ハザードマップを重ねる」の遷移で塗りが洪水になることを確かめる
7. デモ台本の該当場面(チップ操作)を T9 で直す旨を PR 説明に書く

**テスト**: `map-layers.test.ts`、`hazard-map.test.ts` の更新、既存テストが全部通る。

**実機確認**: peek 状態の地図の可視領域(iPhone 15 相当と小型端末)、シートのドラッグと地図のドラッグの競合、特大文字サイズでのボタンと丸ボタンの重なり、やさしい日本語モード、デモモードのバナー表示時の高さ。

**完了条件**: F-01 拡張、F-07 変更、F-14 変更の受入条件(`requirements.md`)。既存の6レイヤー(避難所、車中泊、水位、被害、規制、ハザード)と人口が移行前と同じに見える。

**注意**: `react-native-gesture-handler` は使わない(ルート設定が無い)。`zIndex` は面オーバーレイに効かない(既存の知見)。

3. 生成した JSON の件数、確率の範囲、市域の外接矩形を確かめる。市域の最大値と最小値を `docs/quake-ground-layers.md` §2.2 に追記する

5. `api-spec.md` と出典カードを更新する

**テスト**: 上記2件。

**実機確認**: 不要(UI に触れない)。JSON のサイズ(100KB 前後)だけ確認する。

**完了条件**: `quake-mesh.json` が市域全体を覆い、テストが通る。`docs/quake-ground-layers.md` §5 の「市域内の最大値と最小値」が埋まる。

**注意**: J-SHIS の呼び出し上限は未公表。200ms 間隔、キャッシュ、CSV 経路を守る。JSON は「加工して作成」した成果物で、出典表記を伴う。
