## 2. 設計の原則

既存の作りに倣い、次の6点を守る。

1. **静的化**: 新しいデータはビルド時のスクリプトで市域ぶんを切り出して同梱する(人口レイヤー F-14 と同じ)。実行時に外部 API を叩かない(NF-04)。例外はタイル(F-07 と同じ扱い)
2. **出典はレイヤー単位**: いまはハザードパネルが洪水ポータルの出典を1つの定数で出しているが、地理院タイルが加わるので、レイヤーの型に出典を持たせ、表示中のレイヤーの出典をすべて出す(NF-06)
3. **色の共通言語を守る**: 状態色(緑、橙、赤、灰)は避難所と水位のためのもので、新しいレイヤーには使わない。人口の川藍、ハザードタイルの暖色と区別できる色相を地震レイヤーに与える
4. **文言はカタログ経由**: 固定文言はすべて `PLAIN_JAPANESE_COPY` に標準と平易版を持たせる(F-13)。伝承碑の碑文と微地形区分の名称は原文のまま出し、読みだけ添える
5. **たたみ方は既存に合わせる**: 詳細シートは画面下の自前シート。新しい部品は人口レイヤーの実装を写す
6. **地図を広く保つ**: 地図の上に常時置くものは、上部のボタン1つ、下部のシート1枚、塗りか区域があるときの凡例1行までにする。選択肢はシートの中に置き、既定状態で地図が画面高の70%以上見える(§3.9)

## 3. 機能設計

### 3.1 F-15 地震ハザードレイヤー

#### 3.1.1 データ生成

`scripts/quake-hazard.py` を新設し、`src/constants/quake-mesh.json` を出力する。
処理は次のとおり。

1. 市域の外周を国土数値情報の行政区域(N03、`scripts/flood-population.py` と同じキャッシュ)から取る
2. 市域の外接矩形を覆う 250m メッシュ(3次メッシュの16分割)を列挙し、市域と交差するものだけ残す。約1,000枚になる見込み
3. 各メッシュの中心座標で J-SHIS の2つの API を呼ぶ。地震ハザード情報 API(`pshm/Y2024/AVR/TTL_MTTL`)から `T30_I50_PS`、`T30_I55_PS`、`T30_I60_PS`、`T30_P03_SI` を、表層地盤情報 API(`sstrct/V4`)から `JCODE`、`JNAME`、`ARV` を取る。応答は `.cache/quake-hazard/` に保存し、再実行では API を呼ばない
4. 呼び出しは 1件ずつ 200ms 空け、403 が返ったら 60秒待って再試行する。上限に当たり続ける場合は、J-SHIS のダウンロードページから1次メッシュ 5030 の CSV を手で取得し、`--csv` で読ませる経路を用意する
5. メッシュ矩形を市域で切る。切り方は人口レイヤーと同じ
6. 地震本部の5段階(§3.1.2)ごとにメッシュを融合(shapely の `unary_union`)し、区分あたり1つの多角形群にする。描画する面をセル数(約1,000)から区分数(最大5)に減らすためで、セルごとの値は融合せずに残す

出力は次の形にする。

```json
{
  "meta": { "version": "Y2024", "fetchedAt": "2026-09-20", "cells": 1012, "mesh": 250 },
  "cells": {
    "5030458834": { "p50": 0.39, "p55": 0.095, "p60": 0.021, "si": 5.8, "arv": 1.84, "jcode": 12, "jname": "自然堤防" }
  },
  "classes": [
    { "bucket": 3, "polys": [{ "outer": [[130.73, 33.74], ...], "holes": [] }] }
  ]
}
```

`cells` はメッシュコードで引く辞書で、形状を持たない。
`polys` の `holes` は別の区分に囲まれた部分(低地の中の台地など)で、`Polygon` の `holes` に渡す(生成時に 11 か所あった。穴を空けないと内側の区分の塗りと重なって濃く見える)。
250m メッシュの矩形はコードから計算できる(JIS X 0410 の区画方式。市内7地点で J-SHIS が返したコードと算出結果が一致することを確認済み)。
`classes` は塗るための融合済み多角形で、区分ごとに1件である。
数値は小数3桁に丸める。
サイズは整形前で 160KB 前後(2026-09-12 生成時 159KB。`cells` が大半)。人口メッシュ(202枚、55KB)より大きいが、実行時に読むのはバンドル済みのオブジェクトなので問題ない。

#### 3.1.2 定数

`src/constants/quake-map.ts` に次を置く。

- `QUAKE_CELLS`: メッシュコードから値(確率3値、計測震度、増幅率、微地形区分)を引く辞書。形状は持たない
- `QUAKE_CLASSES`: 区分ごとに融合した多角形を `LatLng[][]` に変換した配列(人口レイヤーの `POPULATION_CELLS` と同じ変換)
- `QUAKE_BUCKETS`: 地震本部の5段階。`p55`(30年以内に震度6弱以上)で塗り分ける

| 区分       | 条件           | 塗り                          |
| ---------- | -------------- | ----------------------------- |
| 0.1% 未満  | p55 < 0.001    | 同一色相の 10% 不透明度       |
| 0.1〜3%    | 0.001 〜 0.03  | 22%                           |
| 3〜6%      | 0.03 〜 0.06   | 36%                           |
| 6〜26%     | 0.06 〜 0.26   | 52%                           |
| 26% 以上   | 0.26 以上      | 68%                           |

  色相は赤茶(`#9A4B2F` を候補)にする。
  川藍(人口)、洪水タイルの黄からピンク、土砂タイルの黄と赤、デモの紫のどれとも離れた色相を選んだ。
  実機で洪水タイルと重ねて判読できることを確かめてから確定する
- `QUAKE_STROKE`、`QUAKE_SELECTED_STROKE`、`QUAKE_SELECTED_STROKE_WIDTH`: 融合面の縁と、選択したセルの矩形(コードから復元)の枠線。塗りは値の符号として使い、選択で変えない
- `QUAKE_ATTRIBUTION`: 「出典: J-SHIS 地震ハザードステーション(防災科学技術研究所)2024年基準 NIED作成版を加工して作成」
- `FUKUCHIYAMA_FAULT`: 上端2点 `(130.726, 33.936)`、`(130.81558, 33.65734)`、名称、規模「M7.2 程度」、確率「30年以内 ほぼ0〜3%」、出典「地震本部の長期評価」
- `JNAME_READING`: 微地形区分の名称に添える読み(`谷底低地` → `たにそこていち` など)。市域に現れる区分だけを持ち、無い名称は読みなしで出す

#### 3.1.3 ホーム画面(S-01)

- レイヤー選択シート(§3.9)の「塗り」に「地震のリスク」を足す。塗りは1つしか選べないので、人口や洪水浸水想定との重なりは起きない。既定は塗りなし
- 描画順は既存の再マウント制御に倣う。塗りを先に、区域タイルを後にマウントし、タイルの `key` に塗りの種類を含める
- `QuakeLayer` は `classes` の多角形を区分ごとに `Polygon` で描く(最大5件)。セル単位の `Polygon` は作らない。人口レイヤー(202枚を1枚ずつ描く)と違い、面の数と頂点数を抑えるためで、react-native-maps では多数の面や頂点が iOS で描画とメモリの負荷になると報告されている
- タップは `MapView` の `onPress` で受け、座標から 250m メッシュコードを計算して `cells` を引く。選択中のセルは、コードから計算した矩形を枠線だけの `Polygon` 1枚で示す。マーカーの押下が地図の押下としても届く既存の問題には、既存のタイムスタンプによる譲り合いをそのまま使う
- 福智山断層帯は `Polyline` で引く。線色は `AppColors.ink`、太さ 2、破線。凡例に「福智山断層帯(断層モデルの上端、深さ3km)」と書く
- 選択は `MapSelection` に `{ kind: 'quake'; index: number }` を足す。タップの譲り合いは人口と同じ(120ms 遅らせ、ピンと線が押されていたら譲る)

#### 3.1.4 凡例

凡例は §3.9 の凡例ストリップに載せる。

- 1行表示: 5段階の見本と両端のラベル(0.1% 未満、26% 以上)、出典
- 展開表示: 5段階の区分名、断層線の見本と名称、注意書き「確率は相対的な目安で、安全度ではなく危険度を示します」(地震本部の解説に合わせる)、出典

#### 3.1.5 詳細シート(S-05)

`QuakeDetailSheet` を人口の詳細シートに倣って作る。

| 行           | 内容                                                                      |
| ------------ | ------------------------------------------------------------------------- |
| 見出し       | 「この場所の地震のリスク」                                                |
| 主値         | 「今後30年に震度6弱以上」 9.5%(区分名「6〜26%」を添える)                  |
| 副値         | 「震度5強以上」 39%、「震度6強以上」 2.1%                                 |
| 地盤         | 「地盤: 自然堤防(しぜんていぼう)」「揺れの増幅: 1.84倍」                  |
| 注意         | 凡例と同じ注意書き                                                        |
| 出典         | `QUAKE_ATTRIBUTION`                                                       |

数値は小数1桁で出す。
読みはやさしい日本語モードのときだけ添える。

#### 3.1.6 性能の逃げ道

区分ごとに融合した多角形は、頂点が区分の境界(階段状の縁)にしか無いので、セル約1,000枚を個別に描くより面の数も頂点数も少ない。
それでも 9/20 の判断日に実機で地図の移動やズームが引っかかるなら、生成スクリプトの `--mesh 500` で4枚を1枚に集約してから融合する(確率は平均、地盤は面積の大きい区分)。凡例に「500m メッシュに集約」と書き、詳細シートには平均であることを注記する。
頂点を間引く案(shapely の `simplify`)は T2 で取り下げた。区分ごとに別々に間引くと隣り合う区分の共有辺がずれて隙間と重なりができ、頂点は 3,000 弱(2026-09-12 生成時 2,861)で間引く必要もない。

画像1枚を地図に貼る `Overlay` は使わない。
react-native-maps の `Overlay` は iOS で表示されない報告があり、透過度も Google Maps 向けのみで、Apple Maps では制御できない。

#### 3.1.7 要約カードへの1行(ストレッチ)

自宅ピンが設定されていれば、要約カードに「自宅の地点: 30年以内に震度6弱以上 ◯%(地盤: ◯◯)」を1行出す。
自宅ピンの座標を含むセルを `QUAKE_CELLS` から引くだけで済むが、審査までの時間が足りなければ落とす。

### 3.9 地図の操作 UI の再設計(F-01 拡張)

#### 3.9.1 いまの問題

ホーム(S-01)は、左上にレイヤーのチップ7個を2段に置き、ハザードを点けると下部に種別チップ4個と凡例と出典のパネル、人口を点けると凡例、その下に要約カード(既定で展開)が積み上がる。
v1.6 で地震、地形、伝承碑を同じ形で足すと、チップは10個3段になり、塗りは洪水、地形、地震、人口の4種が重なりうる。
チップと下部の積み上げで地図が画面の半分近くまで狭まり、どの塗りを見ているのかも分かりにくくなる。

満たしたいのは次の3点である。

- わかりやすさ: いま地図に何が出ていて、色が何を意味するかが一目で分かる
- 地図の広さ: 平常時の既定状態で地図が画面高の70%以上見える
- 慣行に沿う: 地図アプリで広く使われている操作の型に合わせ、説明なしで使える

#### 3.9.2 方針

地図アプリ(Apple マップ、Google マップ)とモバイルの設計指針(Apple Human Interface Guidelines のシート、44pt の操作対象、段階的開示)に倣い、次の5点を方針にする。

1. **段階的開示**: 地図の上には「いま出ているもの」だけを置く。何を出すかの選択は1つのボタンから開くシートに集める
2. **選ばせるより見分けさせる**: シートの項目には一行の説明と色見本を添え、名前だけで判断させない
3. **排他は UI の形で表す**: 面の塗りは同時に1つしか読めないので、切替スイッチの並びではなくラジオ(1つ選ぶ)にする
4. **下部は一枚**: 要約、レイヤー選択、詳細のどれもボトムシート1枚の中身として切り替え、積み上げない
5. **触れる大きさと読める大きさ**: 操作対象は 44pt 以上。文字サイズ設定と VoiceOver は既存の部品(`AppText`、`accessibilityLabel`)をそのまま使う

#### 3.9.3 画面の構成

```
┌──────────────────────────────┐
│ 直方ベース                    │  ヘッダー(既存)
├──────────────────────────────┤
│ [≡ レイヤー 2]        (⌂)(➤) │  上部: 左にレイヤーボタン(数字は塗りと区域の有効数)
│                              │        右に既存の丸ボタン
│                              │
│            地  図            │  既定状態で画面高の 70% 以上
│                              │
│                              │
│ ■■■■■ 0.1%未満   26%以上   ⓘ │  凡例ストリップ(塗りか区域があるときだけ、1行)
│ 出典: J-SHIS(防災科研)…      │
├──────────────────────────────┤
│ ── 水位 平常 ・ 避難所 開設なし ▴ │  ボトムシート peek(1行、56pt 以下)
└──────────────────────────────┘
```

「地図が見える割合」は、`MapView` の高さからボトムシートの peek と凡例ストリップの高さを引いた値を、安全領域を含む画面高で割ったものとする。
タブバーは地図の上に浮いているので、その下の地図も見える扱いにする。

**上部のレイヤーボタン**は、既存のチップ行(2段)を置き換える。
ラベルは「レイヤー」で、塗り(選んでいれば1)と区域の有効数をバッジで示す。伝承碑は既定で表示なので数えない(数えると初期状態から「1」が出て、何かを選んだように見える)。
チップ行の廃止で上部の占有は1行(44pt)になる。

**凡例ストリップ**は、塗りか区域が出ているときだけボトムシートの上端に出る。
1行目は色見本とラベル(塗りは両端のラベル、区域は見本ごとの名前)、2行目は出典(NF-06 のため塗りか区域がある間は常に見せる)。
右端の ⓘ で展開し、区分名、注記、断層線の見本を読める。
展開はボトムシートの中身として出す(積み上げない)。
実装(T1)では専用の展開表示を作らず、ⓘ でレイヤー選択シートを開く。選択中の塗りと区域の下に凡例の全文が出るので、同じものを2か所に持たない。
区域の凡例は区分名(警戒区域、特別警戒区域)が土石流と急傾斜地で同じなので、帯では色見本の前にレイヤーの短い名前(`label`)を置いて見分けさせる。

**ボトムシート**は1枚で、中身を3つの状態で切り替える。

| 状態         | 中身                                                         | 高さ                     |
| ------------ | ------------------------------------------------------------ | ------------------------ |
| peek(既定)   | 要約1行(水位の状態と開設中の避難所数)、取得失敗の警告        | 56pt 以下                |
| 要約         | 既存の要約カードの全行(最寄り避難所2行、AR への導線、川の防災情報) | 内容ぶん(画面高の 40% まで) |
| レイヤー選択 | §3.9.4 の一覧                                                | 画面高の 55%。中はスクロール |

ピンや塗りをタップしたときの詳細シートは、いまと同じくボトムシートの位置に要約の代わりに出る。
ハンドルのドラッグとタップで peek と要約を行き来し、レイヤーボタンでレイヤー選択に切り替える。
レイヤー選択は閉じるボタンと、シート外の地図タップで peek に戻る。

#### 3.9.5 状態の持ち方と描画順

レイヤーの状態は `src/state/map-layers.ts` に純粋な reducer として置き、ホーム画面が `useReducer` で持つ。

```ts
type MapLayerState = {
  pins: Record<'shelters' | 'carShelters' | 'water' | 'damage' | 'traffic', boolean>;
  fill: 'none' | 'flood' | 'quake' | 'landform' | 'population';
  areas: Record<'landslide' | 'houseCollapse', boolean>;
  lore: boolean;
};
```

`lore` と `toggleLore` は伝承碑の T5 で足す(T1 の時点では使う画面が無く、使われない状態を置かない)。

`areas.landslide` は `HAZARD_LAYERS` の `debrisFlow` と `steepSlope` の2タイルを同時に出す(2026-09-12 決定)。タイルの定義は市の Web 版と同じ2件のまま残し、切替と凡例だけをまとめる。
塗りが1つになるので、Apple Maps の面オーバーレイの描画順(マウント順)の制御は、塗り → 区域タイル → ピンの順に子を並べ、区域タイルの `key` に `fill` を含めるだけでよい。
いまの「人口とハザードの表示状態を互いの `key` に入れる」制御は不要になる。
